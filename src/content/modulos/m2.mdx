## Essencial

Dá para usar o Claude Code sem saber como ele funciona. Só que três coisas que parecem caprichos dele, como "esqueceu o que combinamos", "ficou lento de repente" e "o limite acabou cedo", têm causa mecânica. Esta página mostra o mecanismo para você parar de adivinhar.

### O laço: coletar, agir, verificar

A cada pedido, o Claude Code entra num laço. Ele **coleta** contexto, **age** e **verifica** o resultado, e repete até concluir. As fases se misturam: ele lê durante a ação e roda testes no meio da edição.

Quem raciocina é o **modelo**. Quem age é o conjunto de **ferramentas**. O Claude Code é a camada que fornece as ferramentas e controla o que o modelo vê. Cada resultado de ferramenta volta para o modelo e informa o passo seguinte. Por isso um pedido simples pode virar dezenas de chamadas, e por isso o contexto enche.

Você faz parte do laço. Esc interrompe e preserva o que já foi feito. É a forma mais barata de corrigir o rumo, e o [M3](../m3/) mostra como.

### As ferramentas que ele tem

A documentação agrupa as ferramentas embutidas em cinco categorias:

| Categoria | O que o Claude consegue fazer | Ferramentas (nomes exatos) |
|---|---|---|
| **Arquivos** | Ler, editar, criar | `Read`, `Edit`, `Write` |
| **Busca** | Achar arquivos por nome, procurar texto | `Glob`, `Grep` |
| **Execução** | Rodar comandos, testes, git | `Bash`, `PowerShell` |
| **Web** | Pesquisar e ler páginas | `WebSearch`, `WebFetch` |
| **Código** | Ver erros de tipo, achar definições | `LSP`, com plugin de inteligência de código |

Há ainda ferramentas de orquestração, como `Agent` (cria um subagente) e `AskUserQuestion` (pergunta algo a você). A lista completa fica em [Tools reference](https://code.claude.com/docs/en/tools-reference.md).

Os nomes importam porque são as palavras que você escreve nas **regras de permissão** do [M7](../m7/). Duas regras úteis desde já:

- **Ler não pede licença; mexer pede.** Na tabela da documentação, `Read`, `Glob` e `Grep` não exigem permissão. `Edit`, `Write`, `Bash`, `WebFetch` e `WebSearch` exigem, no modo manual.
- **Em macOS, Linux e WSL, `Glob` e `Grep` não vêm por padrão.** O Claude procura com `find` e `grep` pelo `Bash`. No Windows nativo elas vêm. Se a busca do seu sistema parecer diferente da de um colega, é isso.

### A janela de contexto: a memória de trabalho

O **contexto** é tudo que o modelo enxerga num dado momento: o que carrega sozinho (instruções do sistema, `CLAUDE.md`, memória automática, nomes de ferramentas e descrições de skills), a conversa, os arquivos lidos e as saídas de comandos. Ele tem tamanho limitado e só cresce.

As larguras da figura são ilustrativas. Os números reais você mede com **`/context`**, que mostra o uso por categoria: instruções do sistema, ferramentas, skills, mensagens e espaço livre. Faça isso na Ficha 1.

**O que sobrevive à compactação.** Nem tudo some. A tabela resume o que a documentação diz:

| Item | Depois do `/compact` |
|---|---|
| Instruções do sistema e estilo de saída | Continuam valendo |
| `CLAUDE.md` da raiz, regras sem `paths:` e memória automática | Relidos do disco |
| O plano escrito em modo plano | Relido do disco |
| Arquivos que o Claude leu ou editou | Até **cinco** são relidos, os mais recentes; arquivo grande volta só como referência |
| Instruções que você deu **só na conversa** | Resumidas. Podem perder detalhe |
| Saídas de comandos, leituras antigas | Resumidas |

A lição prática cabe numa linha: **regra que precisa durar vai no `CLAUDE.md`**, não na conversa. O [M6](../m6/) ensina a escrever um bom.

**Quando enche.** O Claude Code compacta sozinho perto do limite, então a sessão não morre. Mas você pode agir antes, e é melhor:

| Situação | Faça |
|---|---|
| Vai começar uma tarefa longa com a conversa cheia | `/compact` com instruções do que guardar |
| Vai para um assunto sem relação | `/clear`: conversa nova, contexto vazio |
| Precisa ler muita coisa só para pesquisar | Peça a um subagente: as leituras ficam no contexto dele, só o resumo volta |
| Quer saber quanto sobrou | `/context` |

### O cache: por que trocar de modelo no meio custa

A cada mensagem sua, o Claude Code manda **a conversa inteira** de novo para a API, porque o modelo não guarda nada entre pedidos. Só funciona rápido e barato por causa do **cache de prompt**: a API reconhece o começo do pedido, que é idêntico ao do turno anterior, e relê esse trecho a uma tarifa menor, processando só o que é novo.

A comparação é por **prefixo exato**. Mudou algo no começo, tudo depois precisa ser refeito. O Claude Code ordena o pedido para o que muda menos ficar na frente:

| Camada | Conteúdo | Muda quando |
|---|---|---|
| Sistema | Instruções, definições de ferramentas | O conjunto de ferramentas muda |
| Projeto | `CLAUDE.md`, memória, regras | A sessão começa, ou após `/clear` ou `/compact` |
| Conversa | Suas mensagens, respostas, resultados | A cada turno |

Daí sai a regra que paga a página inteira:

| Derruba o cache (próximo turno lento e caro) | Preserva o cache |
|---|---|
| Trocar de modelo com `/model` | Trocar o modo de permissão (Shift+Tab) |
| Ligar o modo rápido (`/fast`) | Editar arquivos do repositório |
| Compactar (`/compact`) | Invocar uma skill ou comando |
| Conectar ou remover um servidor MCP sem busca de ferramentas | Rebobinar com `/rewind` |
| Mudar o esforço, na maioria dos modelos (*) | Criar um subagente (ele tem cache próprio) |

(*) Com assinatura ou chave de API, Sonnet 5.5, Opus 5.5 e Haiku 5.5 mantêm o cache ao mudar o esforço. Em Bedrock e Google Cloud, não.

Duas observações para não se assustar. Primeiro, **editar o `CLAUDE.md` no meio da sessão não derruba o cache, mas também não vale**: o arquivo é lido na abertura, e a versão nova só entra no próximo `/clear`, `/compact` ou reinício. Segundo, o custo é de **um turno**: depois ele reconstrói o cache e volta ao normal.

A recomendação da documentação é simples: **escolha modelo e esforço no começo da sessão e deixe o `/compact` para os intervalos entre tarefas.** Para ver o cache funcionando, `/usage` mostra uma linha `Prompt cache (main)` com a taxa de acerto, e a Ficha 3 faz isso com números.

### Modelos, esforço e raciocínio

Três botões, três efeitos diferentes:

| Botão | O que muda | Como mexer |
|---|---|---|
| **Modelo** | Capacidade, velocidade e consumo | `/model`, ou `claude --model <alias>` |
| **Esforço** | Quanto ele raciocina antes de agir | `/effort`, ou `claude --effort <nível>` |
| **Raciocínio (thinking)** | Mostrar ou esconder o que ele pensou | Alt+T (Windows e Linux) ou Option+T (macOS); Ctrl+O mostra o texto |

**Modelos.** Use os apelidos, que apontam para a versão recomendada e se atualizam:

| Apelido | Para que serve |
|---|---|
| `sonnet` | Trabalho diário de código |
| `opus` | Raciocínio mais pesado, decisões de arquitetura |
| `haiku` | Tarefas simples e rápidas |
| `opusplan` | Opus no modo plano e Sonnet na execução (cada troca de modo é troca de modelo, com cache novo) |

Na API da Anthropic, em 13/11/2026, a documentação resolve `sonnet` para Sonnet 5.5, `opus` para Opus 5.5 e `haiku` para Haiku 5.5. Em Bedrock, Google Cloud e Foundry, os apelidos podem apontar para versões mais antigas. Para fixar uma versão, use o nome completo.

**Esforço.** Controla o raciocínio adaptativo: o modelo decide quanto pensar em cada passo, dentro do teto do nível. Os níveis em Sonnet 5.5, Opus 5.5 e Haiku 5.5 são `low`, `medium`, `high`, `xhigh` e `max`, e o padrão desses três é `medium`. A documentação sugere `low` para ideias e mudanças pequenas, `medium` para trabalho diário com escopo claro e `high` quando a verificação importa ou há casos de borda. `max` vale só para a sessão atual.

**Raciocínio.** Nesses mesmos modelos você **não consegue desligar** o raciocínio: o esforço é o controle. A frase "pense com calma" no pedido é texto comum. Mexa no `/effort`.

Esse conjunto também explica o limite de uso do plano. Raciocínio, leituras e releituras de contexto consomem tokens, e `/usage` mostra quanto do plano você gastou. O [M18](../m18/) trata de medir e economizar.

### O cache expira

Prefixos em cache vencem depois de um tempo parado. Cada pedido que acerta o cache reinicia o relógio. A API oferece duas durações: cinco minutos e uma hora (com escrita mais cara). Numa assinatura, dentro do uso incluído no plano, o Claude Code pede uma hora para a conversa principal. Com chave de API ou crédito de uso, o padrão é cinco minutos. Você pode escolher com a configuração `promptCacheTtl` ou a variável `CLAUDE_CODE_PROMPT_CACHE_TTL`.

Consequência: o primeiro turno depois de uma pausa longa é mais lento. E `/compact` custa mais quando você retoma uma sessão velha, porque o pedido de resumo precisa reprocessar tudo sem cache.

### Onde o cache vive e o que o separa

O cache fica no servidor, onde seu modelo roda, e é separado por modelo, por velocidade e por esforço (na maioria dos modelos). No Claude Code ele também é limitado a uma máquina e uma pasta, porque o início da conversa inclui a pasta de trabalho e o sistema operacional. Duas sessões em pastas diferentes não aproveitam o cache uma da outra.

### Subagentes e cache

Um subagente começa conversa própria, com instruções do sistema e ferramentas próprios. O primeiro pedido dele não lê o cache do pai. Em compensação, o cache do pai fica intacto. Subagentes usam o prazo de cinco minutos mesmo numa assinatura, a menos que você escolha outro.

### Janela de contexto e compactação automática

Alguns modelos têm janela de 1 milhão de tokens, entre eles Sonnet 5.5 e os modelos Fable. Quando você não define nada, a compactação automática roda perto do limite do modelo. Para antecipar, use `/autocompact` com um valor, como `/autocompact 500k`, ou a configuração `autoCompactWindow`. O comando aceita de 100 mil a 1 milhão de tokens.

### Imagens acumuladas

A API limita imagens e PDFs por pedido. Ao chegar perto, o Claude Code remove as mais antigas em lote, e o Claude deixa de vê-las. Se precisar de uma de novo, mande outra vez. Um turno lento por lote removido é esperado.

### O que o laço faz com permissões

Antes de executar uma ferramenta que exige permissão, o Claude Code consulta o modo de permissão e suas regras. É o assunto do [M7](../m7/). O que importa aqui: uma ferramenta negada não executa, e o laço continua com a recusa como informação nova.

</Camada>

<Camada tipo="armadilhas">

### Trocar de modelo no meio de uma tarefa longa

O Claude Code pergunta antes, enquanto o cache está quente. O aviso existe porque o turno seguinte relê tudo sem desconto. Se for trocar, troque no intervalo entre tarefas.

### Dar uma regra importante só na conversa

"A partir de agora, sempre use tabs." Depois de uma compactação, essa frase vive num resumo e pode perder força. Se vale para o projeto, vai no `CLAUDE.md`.

### Editar o `CLAUDE.md` e esperar efeito imediato

A versão nova só entra no `/clear`, no `/compact` ou num reinício. Na sessão em curso, vale a lida na abertura.

### Pedir para "ler o log inteiro"

Um log grande custa o log grande, a cada turno seguinte, até a próxima compactação. Peça a parte que importa (`tail`, `grep`) ou mande um subagente ler.

### Achar que `/compact` é de graça

Ele manda um pedido de resumo e reconstrói o cache da conversa. Compacte nos intervalos, não no meio de um raciocínio.

### Tentar controlar o esforço pelo texto do pedido

"Seja minucioso" não muda nível nenhum. `/effort` muda.

### Confundir `/clear` com `/compact`

`/clear` abre conversa nova e vazia, e a anterior fica disponível em `/resume`. `/compact` continua a mesma conversa, resumida.

</Camada>

   claude -p "Responda apenas: ok" --model sonnet --continue --output-format json | node ferramentas/uso.mjs

   claude -p "Responda apenas: ok" --model sonnet --continue --output-format json | node ferramentas/uso.mjs
