Os três casos de treino

Estes são projetos de treino com clientes fictícios. Eu os criei para praticar o que vendo: um site simples, um sistema com login e um atendente de WhatsApp com regras claras.

Cada caso mostra o mesmo formato: o problema, o que foi entregue e a forma de conferência. Nenhum número aqui é de cliente real.

Caso de treino a · Site

Doce Esquina (confeitaria fictícia)

O problema do cliente

A confeitaria recebe encomendas por mensagens soltas, e muitas chegam sem data, sabor ou quantidade. A dona perde tempo perguntando as mesmas coisas e não tem um lugar para mostrar o cardápio.

O que foi entregue

  1. Um site de uma página, pensado para celular, com apresentação e cardápio.
  2. Um formulário de encomenda que pede os dados principais e, ao enviar, abre o WhatsApp com a mensagem já preenchida.
  3. Um botão de WhatsApp sempre visível na tela do celular.

Como foi conferido

O site passou por 4 verificações automáticas.

Caso de treino b · Sistema

Oficina Boa Estrada (oficina fictícia)

O problema do cliente

A oficina controla as ordens de serviço em papel e planilha. Fica difícil saber em que etapa está cada carro, e dono e atendente acabam dividindo a mesma senha.

O que foi entregue

  1. Um sistema de ordens de serviço para abrir, acompanhar o status e fechar cada serviço.
  2. Login separado para dono e atendente. As senhas são guardadas só como hash, nunca em texto puro.
  3. Um backup ensaiado: a cópia é gerada e a restauração foi testada, para saber que ela funciona de fato.

Como foi conferido

O sistema passou por 74 verificações automáticas.

Caso de treino c · Atendente de WhatsApp

Pet Shop Patas Felizes (pet shop fictício)

O problema do cliente

A equipe responde todo dia as mesmas perguntas de horário, produto e preço. Quando o atendimento é automático, o risco é o robô inventar uma informação que não existe.

O que foi entregue

  1. Um atendente de WhatsApp que responde só com o que está na base de conhecimento da loja.
  2. Passagem para uma pessoa quando o atendente não sabe a resposta, em vez de chutar.
  3. Proteções na saída: a resposta é checada antes de ser enviada.

Como foi conferido

Avaliado em 20 casos de treino com nota 100%, e conferido por 144 verificações automáticas.

A nota 100% vale para estes 20 casos de treino. Não é uma medida de desempenho com clientes reais.

Como eu trabalho

Eu uso o Claude Code para escrever e alterar o código. Não confio só no que a ferramenta gera:

  • Confiro tudo com testes automáticos, que rodam sempre que algo muda.
  • Testo o fluxo com uso real, como um cliente faria no celular.
  • Uma pessoa (eu) revisa tudo antes de qualquer entrega.

O que o atendente NÃO faz

  • Não promete resultado, venda ou prazo que a loja não tenha dito.
  • Não confirma horário, agendamento ou disponibilidade. Isso fica com a equipe.
  • Não inventa preço, produto ou política que não esteja na base de conhecimento.
  • Não substitui uma pessoa: quando não sabe, passa o caso para ela.
